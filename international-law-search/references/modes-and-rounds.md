# Modes and Rounds

## Governing Principle

The user owns mode, scope, branches, seeds, languages, budgets, and stopping. Ask for a decision only when it changes the next round. Keep the visible choice small and concrete; keep operational detail in the source ledger or deep-audit workspace.

## Readiness Interview

Build on information already supplied. Ask one material question at a time rather than presenting a fixed questionnaire. Readiness means the next round has a sufficiently clear:

- research purpose and tentative research question;
- included and excluded issues;
- primary-material, scholarship, doctrinal, theoretical, institutional, regional, or empirical emphasis;
- date, jurisdiction, institution, and language boundaries;
- local seeds and access assumptions;
- output type, mode, next-round budget, and stopping checkpoint.

Offer a recommended default with each question when it would help. If the user cannot yet frame the issue, propose a bounded exploratory round whose purpose is to produce a field map and better choices. Never force a definitive research question before exploration can reasonably supply one.

Before external retrieval, show the concise scope card and obtain approval. Authorized local intake inspection may identify public citations and scope clues, but it does not authorize external retrieval. Approval covers only the stated next round.

## Working Modes

### Quick mode

Use Quick mode for orientation or a bounded starting bibliography, normally 10–20 reliable sources grouped by theme and reading priority. Quick mode does not require a citation graph or audit workspace, persistent state, round metrics, or canonical JSONL.

Quick-mode scope approval authorizes delivery when the approved budget is complete; a second closure confirmation is unnecessary unless a material choice arises. At delivery, offer an upgrade. An upgrade must reuse the existing source ledger and must not restart completed retrieval. A quick result can become the Stage 1 breadth result in standard mode, or its records can be enriched in deep-audit mode.

### Standard interactive mode

Recommend Standard interactive mode for ambiguous or substantial research. It uses Stage 0 through Stage 4, concise checkpoints, user-owned seed selection, and a lightweight source ledger. It need not create a complete audit workspace or graph.

### Deep-audit mode

Use Deep-audit mode when the user requests reproducibility, persistent state, full retrieval logs, validated structured data, graph evidence, recovery across sessions, or systematic corpus maintenance. It follows the same user decision gates as standard mode while enriching the same records. Audit requirements never authorize a wider scope.

Mode choice belongs to the user. The assistant may recommend a mode and explain the tradeoff, but must not silently upgrade, downgrade, or add audit overhead.

## Stages and Checkpoints

### Stage 0: Scope confirmation

Confirm only what is needed for the next round: research question, inclusions, exclusions, languages, access assumptions, mode, next-round budget, and first directions. Do not put exact query strings or branch mechanics in the user-facing scope card. The user may approve, revise, or request one bounded exploratory round.

### Stage 1: Breadth discovery

Map the field without systematic citation tracing. In an ordinary standard round, collect 15–30 candidates across relevant source types, positions, periods, regions, and languages, while reviewing full text only within the approved budget. Present a provisional field map, 5–10 candidate seeds, access and retrieval gaps, planned and actual resource use, and the decision panel.

After the breadth checkpoint, the assistant **must stop**. Stage 2 cannot begin until the user selects or confirms branches and user-confirmed seeds. Do not silently convert influential sources into tracing instructions.

### Stage 2: User-directed depth

Trace only user-confirmed seeds and only within each seed's approved depth and resource budget. Honor instructions to delete a branch, review without tracing, stop following an author or position, or prioritize particular full texts. Newly suggested seeds require user confirmation before tracing. Report each seed's path, useful additions, duplicates, access constraints, and remaining choices at the depth checkpoint.

### Stage 3: Optional targeted gap filling

Offer bounded gap-filling choices only when supported by the checkpoint: for example, a missing language, region, period, tribunal, institution, source type, minority position, recent development, or inaccessible key work. Distinguish a research gap in the literature from a retrieval gap in this search. Do not fill either gap without the user's authorization.

### Stage 4: Closure and delivery

In Standard interactive mode and Deep-audit mode, explicit user authorization is required for closure. “Stop and deliver” authorizes an accurately qualified interim output. Before closure, the user may continue, narrow or delete a branch, change a budget, upgrade mode, or request another bounded round. Quick-mode closure follows its approved-scope rule above.

## Round Budgets

Express each approved round using the dimensions that matter, rather than a vague label alone:

- search time;
- platform count or named platforms;
- query count;
- candidate count;
- full-text review count;
- seed count;
- tracing depth per seed;
- language-specific query, candidate, and review allocations.

Every checkpoint reports planned and actual use. Mark a budget-limited or budget-paused round accurately; a budget-paused result cannot by itself establish saturation. Dynamic saturation requires diminishing new high-relevance results across successive authorized rounds, plus an account of duplicates, coverage, and valuable untraced paths.

## Changes and Upgrades

Within an approved round, refine query wording without returning for permission. Obtain user approval before materially changing topic, mode, language, jurisdiction, source track, seed, depth, output, or resource budget.

Upgrade Quick mode to Standard interactive mode by treating the existing bibliography and ledger as the breadth result, then presenting the breadth checkpoint. Upgrade standard to deep-audit by enriching the same records and creating audit artifacts. Preserve identifiers, discovery provenance, user decisions, access evidence, and review claims; an upgrade must not erase or silently relabel earlier work.

## Decision Language

End each non-final checkpoint with concrete options from the decision-panel template. Adapt labels to the user's language and omit irrelevant controls. Never reduce the choice to an open-ended “What next?” when the evidence supports specific options.
